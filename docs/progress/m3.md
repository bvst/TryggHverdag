#### What GRP-01 delivers, in plain words

- A person joins with a **single-use invitation code** that the admin creates
  and sends however they like. It expires 7 days after it was made, by the
  database's clock. The person types their own name when they join (D-136,
  answer 3). The **first admin** joins with a one-time **bootstrap code** that
  Terraform makes and the owner reads once in Clever Cloud's console (answer 1;
  A-36).
- The phone gets a **device credential:** 256 random bits, only their SHA-256
  stored. **Membership is the session** (D-137): a device authenticates while
  its user is a current member, so removing a member signs out every device of
  that user in the same commit, with no revocation flag to forget. A member
  removed **while walking** keeps their own journey to its end, with heartbeats
  and "I'm home" only (`WALKER_ONLY` access), and is signed out when it ends
  (answer 5).
- The admin **lists members and removes one** in a single transaction across
  every journey the member follows, through SM-10's own removal step, with an
  audit row. The walker **removes a responder from their own journey** (D-122's
  route); anyone else gets the one 404.
- A journey's responders must be **current members of the walker's group,**
  held under the lock. The canary's walker may name its own responder and
  nobody else; the canary's users can have no membership (D-128).
- The worker **withholds its check-in** while the SMS check is not reporting
  (AC25), so a worker whose SMS check nobody sees is paged through
  `staging-worker` instead of going unnoticed (D-122's condition for the
  removal route).
- One migration, `0009`: `groups`, `memberships`, `invitations`, `audit_log`.
- In the app: the join screen, the member screen, and for the admin the invite
  and members screens. In Terraform: the bootstrap code. In CI: `android-e2e`
  starts PostgreSQL and the API for the first L7 flows that need a server.
- 33 acceptance criteria (AC1 to AC30 from the spec, AC31 to AC33 added in
  review loop 1). Better Auth is **not** installed: its value is SMS codes and

#### The `android-e2e` failure and its fix (`b571158`)

**Cause.** With the reason in the log, the failure read (job 118918227742):

```
maestro.js.JsEvaluationException: SyntaxError: <eval>:1:19 Missing space
after numeric literal
CODE_LABEL}:\s*[0-9A-HJKMNP-TV-Z](\s+[0-9A-HJKMNP-TV-Z]){4}(\s*[,.;]\s*...){3
```

Maestro evaluates `${…}` in a flow string as JavaScript, **greedily.** Its
`Env.kt` (`maestro-orchestra-models`, tag `cli-2.10.0`, and the release jar this
repository pins, checked against `MAESTRO_SHA256`) holds the regex
`(?<!\\)\$\{([^$]*)}`: the script runs from `${` to the **last** `}` before the
next `$`, not to the first `}`. Loop 2's `${CODE_LABEL}:` prefix stood before a
regex quantifier `{4}` and `{3}` in two strings (the label's wait and the
group's `childOf`), and no `$` came after, so Maestro took `CODE_LABEL}:\s*…{4}){3`
as one script and failed on it. **Every `android-e2e` run of #96 failed at that
step.**

**A wrong turn, kept so it is not repeated.** GRP-01-AC28's `patterns()` in
`scripts/lib/e2e-android.test.mjs` had read `${NAME}` up to its own `}`, which is
not what Maestro does, so `faa0ed7`'s test file (162 of 162) passed on the broken
flows as well as the fixed ones, and that is how the broken flows got through. A
test that models a tool wrongly passes on code the tool rejects. The fix models
Maestro's own reading.

**Fix.**
- `apps/mobile/e2e/first-admin-invites.yaml`: both label patterns are written
  out in full, with no `{4}` or `{3}` (five characters with `\s+` between them,
  and three more groups after `\s*[,.;]\s*`). One pattern per step, as before.
  The group's own `{5}` stays, because that string holds no `${`. A comment
  quotes Maestro's regex and says why.
- The harness's `asMaestroInterpolates` reads `${…}` with Maestro's two patterns
  (the second turns `\${…}` back into `${…}`): a bare name becomes its `-e`
  value, and any other script, or a name no `-e` passes, throws and names what
  Maestro would evaluate. GRP-01-AC28's `patterns()` uses it.
- **New guard, INF-06-AC11:** no string in a flow holds a `${…}` beside any
  other brace, so Maestro reads each as a bare name. It reads every flow under
  `apps/mobile/e2e/`, and fails if it reads no `${` at all.
